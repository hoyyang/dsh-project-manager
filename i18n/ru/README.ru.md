# Проектная доска (dsh-project-manager 0.20.1) — руководство на русском

то, что у вас **Windows**: часть функций «проектов на диске» там отключена.

## Важно: ограничение Windows

Плагин умеет две вещи: **доска** (канбан) и **«проекты на диске»** (память проекта в `~/.ai`,
через утилиту `ai-memory`, которая требует Python 3 и файловые блокировки `fcntl`).
**На Windows часть «проекты на диске» недоступна** — это видно по жёлтой плашке наверху
доски. Практически это значит:

- доска, группы, карточки, этапы, подзадачи, заметки, ссылки, файлы, репозитории,
  сессии и архив — **работают**;
- импорт проектов с диска, память проекта (STATE), «Вспомнить/выгрузки», слияние
  проектов, автопереносы — **не работают до появления поддержки Windows**.

## Быстрый старт (30 секунд)

1. В сайдбаре под «Плагины» откройте **«Проектная доска»** → **«Новая группа карточек»**,
   введите название, Enter.
2. Внизу любой колонки нажмите **«+ Добавить карточку»**, введите заголовок, Enter
   (Enter добавляет следующую карточку подряд).
3. **«Настройки группы»** — переименование этапов, порядок, общие репозитории.
4. Откройте карточку → **«Новая сессия»**: сессия создаётся и привязывается к карточке.
5. Дальше работаете в сессии; карточка хранит ваши заметки, ссылки, файлы, подзадачи,
   репозитории и список своих сессий.

## Доска

- **Группа карточек = родительский проект**, **карточка = задача**, **колонки = этапы**.
  5 этапов по умолчанию: Анализ / Планирование / Реализация / Тестирование и приёмка / Готово.
- Этапы можно переименовывать, добавлять, менять порядок (в «Настройках группы»).
- Карточки перетаскиваются мышью между этапами; `Alt+↑/↓` — порядок внутри этапа.
- Группы можно сворачивать и перетаскивать.
- **Статистика в шапке группы**: количество карточек (синий счётчик), активные сессии
  («N активных сессий»), число репозиториев и этапов.
- **Счётчики на карточке**: бейдж сессий (зелёный — есть активные, серый — все в архиве)
  и счётчик привязанных проектов.
- **Архив**: кнопка-архив на карточке или перетаскивание в «Архивные карточки»;
  детали в архиве — только чтение, можно вернуть карточку на её этап.
- **Тёмная тема** — переключатель справа в шапке доски.
- Внизу этапа есть поле **«Добавить карточку»** — можно добавлять карточки прямо в колонку.

## Детали карточки

- **«Новая сессия»** — создаёт сессию из карточки: кнопка блокируется на время создания,
  в сайдбаре появляется строка «название карточки · не начата». Сессии получают полный
  доступ и называются по карточке.
- **Сессии этой карточки** — активные сверху, архивные ниже, по времени обновления:
  открыть, архивировать (с подтверждением «остановить и заархивировать», отменяемо),
  восстановить, отвязать.
- **Связать существующие сессии** — поиск по имени/репозиторию, колонки активных и
  архивных, сохранение одним действием. Сессия принадлежит одной карточке.
- **Заметки** — без ограничения длины, ссылки кликабельны, можно сворачивать.
- **Ссылки** — текст + тип (типы настраиваются в «Управлении типами») + URL; массовое
  добавление, перетаскивание для порядка, копирование.
- **Файлы** — через системный выбор файлов или вставкой путей (каждая строка
  проверяется: существует / папка / не найдена / уже привязана).
- **Этапы и подзадачи** — переключение этапа кликом по шкале, чек-лист подзадач.
- **Репозитории карточки** — свои репозитории вдобавок к общим репозиториям группы.

---

## Репозитории

- В «Настройках группы» задаются **общие репозитории** — они автоматически попадают
  в новые карточки; каждая карточка может добавить свои.
- Кандидаты берутся из рабочих пространств DSH и репозиториев, добавленных где-либо
  на доске, либо через «Выбрать папку…».
- В проектных сессиях репозитории видны как `repos/<имя-репозитория>/` (симлинки) с
  файлом `AGENTS.md` со списком; если имя занято другим путём — будет `имя-2`.

## Сайдбар «Проектная зона» (project hub)

- Сверху закреплено рабочее пространство хаба, каждая группа — дочернее пространство.
- В строках групп показывается число незаархивированных сессий; сессии «вложены» под группу.
- Пустые сессии, которые DSH обычно скрывает, отображаются как «название карточки · не начата».
- Кнопка **«+»** в сайдбаре сначала предлагает выбрать карточку, затем создать/выбрать сессию.
- Рядом с «Плагины» кнопка **«Проектная доска»** со счётчиком «N в работе».
- Если «Проектной зоны» в сайдбаре нет — она появляется после первой проектной сессии;
  до этого пользуйтесь кнопкой «Проектная доска».

## Что умеет ИИ-агент

Плагин регистрирует инструменты, которыми агент может управлять доской
(без параметра `card` действуют на карточку текущей сессии):

- `card_manage` — создать/изменить/удалить карточку;
- `repo_manage` — репозитории карточки и группы;
- `phase_move` — перевести карточку на другой этап;
- `task_manage` — подзадачи (добавить/отметить/удалить);
- `landfill` — чтение/запись памяти проекта (на Windows отключён).

Пример запроса: «Переведи эту карточку на этап “Тестирование и приёмка” и добавь
подзадачу “прогнать регресс”» — агент вызовет `phase_move` и `task_manage`.

## Настройки группы

- Имя группы.
- Папка на диске для «проектов на диске» (**на Windows неактуально**).
- Этапы: переименование, порядок, добавление/удаление.
- Общие репозитории: путь, имя, роль.
- Привязки к проектам памяти (**только при работающем landfill**).
- Архивные карточки.

## Где хранятся данные

- `$DSH_HOME/dsh-project-manager/board.json` — доска (группы, карточки, этапы,
  репозитории).
- `$DSH_HOME/dsh-project-manager/events.jsonl` — журнал событий (кто/когда/что).
- `$DSH_HOME/dsh-project-manager/hub\` — рабочее пространство «проектной зоны»
  и генерируемые `AGENTS.md`.
- `merges.json` / `migrations.json` / `backups\` — появятся, когда будет доступен landfill.
- Запись на доску — атомарная, изменения сериализованы.

## Настройка через профиль (необязательно)

Плагин работает без настройки. Переопределения добавляются в
`C:\Users\user\.dsh\profiles\desktop\cordis.patch.yml` отдельной записью по `id`
(не внутри `insert:`):

```yaml
- id: dsh-project-manager
  config:
    dataDir: ''                              # по умолчанию <DSH_HOME>/dsh-project-manager
    aiRoot: ''                               # по умолчанию ~/.ai
    landfill: true                           # false = только чтение (на Windows и так выключено)
    hubTitle: Проектная зона
    projectSessionMode: danger-full-access   # или inherit — как глобальные права
    memoryMaxBytes: 6000                     # лимит раздела памяти в системном промпте
```

Папка landfill задаётся в настройках группы, а не здесь.

## FAQ

- **Нет «Проектной зоны» в сайдбаре?** Она регистрируется после первой проектной сессии;
  до этого — кнопка «Проектная доска».
- **Группы не вложены в хаб?** В настройках вида списка рабочих пространств выберите
  группировку «по дереву рабочих пространств».
- **Спрашивают папку для landfill?** Новые и переносимые проекты кладутся в папку группы;
  спрашивается один раз, меняется в настройках группы. На Windows недоступно.
- **«Восстановить» серое?** В вашей сборке DSH нет `workspaceRegistry.unarchiveSession`;
  нужен плагин `dsh-manage-sessions` и его патч ядра.
- **«Выбрать папку…» стал текстовым полем?** При удалённом/веб-доступе системный диалог
  недоступен — введите абсолютный путь вручную.
- **Почему плашка «Функция проектов на диске не включена»?** Это и есть ограничение
  Windows (нужен `fcntl`); остальные функции доски работают.

## Удаление плагина (если понадобится)

1. `POST /_dsh/dsh-project-manager/api/hub/cleanup` — убрать рабочие пространства хаба
   (сессии и файлы сохранятся) — либо удалить их вручную.
2. Встроенным CLI: `dsh plugin --profile desktop remove dsh-project-manager`, затем
   перезапустить DSH.
3. Данные остаются в `$DSH_HOME/dsh-project-manager/` — удалить вручную при желании.
